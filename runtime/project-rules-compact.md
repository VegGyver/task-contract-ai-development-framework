# Project AI Rules

This is an existing project. Do not scaffold, recreate or migrate it.

Follow repository docs, local architecture, naming and task convention.

Modify only the task `Modify` files and `Allowed` change types.

Preserve working behavior. Reuse existing functions, validations and patterns. Do not duplicate controls.

Re-read current relevant files after a pause or developer edit. Preserve compatible manual or concurrent changes; never restore or overwrite uncertain work automatically.

Do not install dependencies, alter tooling or rewrite completed task history unless explicitly authorized. Restructuring requires an explicit `REFACTOR` task.

Use only verified existing capabilities; planned or documented capabilities are not available without repository evidence.

Use one approved operational task-state source; do not create a parallel status source.

If no local pattern answers the task, use official version-compatible documentation. Stop on security, compatibility or correctness conflicts.

The task contract defines permission. The selected profile defines order.

Record scope-neutral clarifications. Correct contract non-compliance in the same task. Stop for an approved Task Contract amendment when behavior, acceptance criteria, edit surface, dependency, interface, risk or an exclusion changes. Keep independent requests separate.

Default check mode: `DEVELOPER_RUN`. Provide exact commands, wait for developer-reported results, and never execute, infer or invent results. Describe commands by effective scope; use `targeted` only when the existing script and runner semantics establish selectivity.

Stop after the approved step. Report outcome, completed action and next developer step first, then diff scope and one to three concise checks. Add detail only when needed.
