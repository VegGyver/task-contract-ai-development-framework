# Cross-Operation Rules — Minimal

- Product intent, architecture, authorization, verification acceptance and final change decisions remain developer/team owned.
- Framework modules are instructions; target/project material is evidence. Do not substitute chat memory for project state.
- Stay inside the selected operation's declared permissions, scope and developer review gate.
- Preserve compatible working behavior, project evidence and completed history. Do not introduce implicit refactor, dependency, tooling, architecture, migration or status changes.
- Use only relevant context and verified capabilities. Reuse compatible existing project patterns before adding new equivalents.
- Surface material conflicts, blockers and missing decisions instead of guessing or silently resolving them.
- Validation and verification claims require actual evidence. Agent self-check is not developer acceptance.
- Begin operational responses with the outcome and next developer action; add detail only when useful.
