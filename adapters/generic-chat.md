# Generic Chat Adapter

Use only when the host can keep the framework available persistently and bind attachments or project resources.

- Pass adapter ID `generic-chat` through the host integration.
- Bind one attachment/resource as the target; do not ask the user for framework files.
- Let the runner or equivalent host loader assemble the same registered run envelope.
- Use a bounded task contract.
- Ask for a patch or exact replacement limited to the allowed edit surface.
- The developer applies changes and runs checks.
- Do not let chat memory replace repository evidence.
- Start a new task contract for each accepted next step.

A chat without persistent framework availability or target-resource access is incompatible. Do not introduce a temporary bundle or hand-built prompt.
